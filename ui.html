Interface · operator surfaces

Five rules I build operator tools by. Each one is here, running, next to the thing that taught it.

The people who use my software are doing their job while they use it - booking a client, cancelling a render, watching an agent run. Every demo below is the real behaviour, rebuilt small, with the problem it came from and the decision it forced.

One file. No framework, no build step, no dependencies - hand-written HTML, CSS and vanilla JavaScript, same as the rest of this site. Turn JavaScript off and every panel still shows a real state.

Session cockpit · event stream

State admits what it doesn't know.

The cockpit that supervises my AI coding runs streams 21 typed event kinds, each carrying a monotonic sequence number. Drop the connection and the feed replays from the last cursor it held - and a replay that looks continuous but isn't is worse than a hole, because it turns a missing event into a wrong conclusion. So the hole gets drawn: how many events were lost, and the sequence number the feed is complete from. A gap I can see is a bug report.

Problem
Reconnect used to stitch the feed back together and quietly swallow whatever happened while it was away.
Constraint
The server keeps a bounded buffer. Some replays genuinely cannot be completed.
Decision
Render the gap with its size and its resume point. Never interpolate, never silently trim.

Dependency catalog · blast radius

If the data is yours, draw it yourself.

This is a real answer out of the catalog of the AI estate on this machine - 364 entries, 1,306 edges, rebuilt from source, queried by coding agents over MCP before they change anything. At the centre is the orchestrator's advance() step and the thirteen things that hold it. Placement is a golden-angle spiral, about forty lines of arithmetic; there is no charting library on this page. When the data is mine and the shape is this specific, a dependency costs more than the maths does.

Problem
"What breaks if I touch this?" was being answered from memory of the architecture.
Constraint
The graph is small, oddly shaped, and mine. A generic chart library would fight it.
Decision
Hand-rolled layout, real ids on screen, and a selection that dims everything it does not touch.

Scheduler · capacity guardrail

The interface enforces the invariant.

A scheduler that replaced a paper process at a pediatric therapy clinic. Capacity used to live in one person's head, which meant it was argued about after the fact, once the day was already too full. Now the workload model runs in the interface: every booking charges its contact time plus the documentation, turnover and recovery it drags behind it, in quarter-hour steps against a real day. Past the line the booking is refused, not flagged - a warning you can click through is a rule nobody keeps.

Problem
The true cost of a booking was invisible at the moment somebody made it.
Constraint
Non-contact time is most of the overrun and none of it is on the calendar.
Decision
One model, computed in the UI, shown as it fills - and a hard block with the arithmetic attached.

House convention · every page, every tool

Ambiguity is a bug in the conversation.

Every page in my tools carries a per-section dev label - A, B, C down the page. It costs one div per section and it deleted a whole class of round-trips: "fix section B" lands somewhere exact, whether it comes from a client, from me a month later, or from an AI agent editing the file. Without them the same note arrives as "the middle bit under the search thing," and finding out which bit that was takes two more messages and a screenshot.

Problem
Feedback pointed at regions of a screen that had no names.
Constraint
It had to cost nothing to apply and nothing to remember.
Decision
Letters restart per page, one tag per section, mandated for new UI - and shipped visible, not hidden behind a flag.

Media queue · local GPU box

Nothing vanishes silently.

This is the job queue for a generation box on my desk. Operators would hit cancel and then have no idea whether the click landed - the tile just sat there, or disappeared a beat later with nothing said. So every tile now carries two facts at once: what the backend last confirmed, and what the screen is showing you. Your click changes the second one immediately; only the 2.5-second poll changes the first. A cancelled job announces its own death and holds its place for four seconds before it leaves.

Press Walk me through it and the demo queues a job, lets it resolve a preview, cancels it, and waits out the tombstone - the event log narrates every step and says who caused it, you or the backend.

Problem
A cancel with no feedback reads as a broken button, so it gets pressed again.
Constraint
The backend is authoritative and polls on a 2.5-second cycle. The UI cannot pretend to know sooner.
Decision
Optimistic intent, never optimistic outcome: show the state it is entering, and leave a tombstone when it ends.
On screen
Each tile prints backend says against screen shows. When they disagree, the tile says so in orange rather than picking one.
